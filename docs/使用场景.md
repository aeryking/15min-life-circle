# 使用场景

> 本文描述「15 分钟生活圈智能体检与规划助手」的典型用户与使用流程。
> 文中数字均为示意，实际数值以系统对样例社区的真实计算结果为准。

## 目标用户一览

| 用户 | 核心诉求 | 主要使用功能 |
|---|---|---|
| 街道办 / 社区规划人员 | 摸清家底、发现短板、给出补点方案 | 等时圈、服务盲区、选址推荐、体检报告导出 |
| 城市规划 / 住建部门 | 多个社区横向对比、考核达标情况 | 多社区对比、评分雷达图、批量体检 |
| 养老服务机构 / 老人家属 | 老人步行能否方便就医、买菜 | 适老化等时圈、AI 问答 |
| 购房 / 租房者 | 评估小区真实生活便利度 | 自定义中心点、设施覆盖统计、AI 问答 |
| 商户 / 连锁品牌 | 找到供给不足、值得开店的位置 | 服务盲区、选址推荐 |
| 研究人员 / 学生 | 获取可复现的可达性分析数据 | 数据导出、算法参数调节 |

## 场景一：街道办年度「生活圈体检」

**角色**：某街道办社区规划科工作人员小王
**痛点**：上级要求年底提交 15 分钟生活圈建设评估，过去靠人工走访和表格统计，耗时两三周，而且只能按直线距离画圈，结论经不起推敲。

**使用流程**
1. 打开系统，在搜索框输入社区名称，或直接在地图上点击社区中心，系统自动完成地理编码并定位。
2. 点击「开始体检」。系统沿多个方向采样，调用路径规划与批量算路接口，按**真实步行路网**生成 15 分钟等时圈，并以热力图显示各位置的步行耗时。
3. 系统自动检索圈内医疗、教育、购物、养老、文体等设施，完成多源 POI 去重清洗，输出各类设施的数量和覆盖率。
4. 地图上以灰色标出**服务盲区**，也就是周边 1 公里步行范围内缺少菜市场、药店或小学的片区。
5. 点击「导出报告」，得到一份 PDF 体检报告，包含总分、雷达图、盲区清单和 AI 生成的文字诊断，可以直接作为汇报材料的附件。

**价值**：评估周期从数周缩短到几分钟；结论基于真实路网而不是直线距离，而且能落到具体点位。

## 场景二：补短板的选址决策

**角色**：同一街道办，拿到体检报告之后
**痛点**：知道缺什么之后，下一个问题是新的药店、菜市场、养老驿站建在哪里能覆盖最多居民。

**使用流程**
1. 在体检结果页选择短板设施类型，例如「药店」。
2. 点击「选址推荐」。系统在候选地块上计算：如果在这里新增一处设施，能消除多少盲区。
3. 地图上标出推荐点位 Top 3，并用前后对比图展示新增设施后的覆盖变化。
   > 示意：「在 A 点新增一家药店，可使药店盲区面积减少约 60%。」
4. 在 AI 助手中追问：「如果只能新建一处，优先建药店还是菜市场？」AI 调用分析结果给出排序和理由。

**价值**：从「发现问题」推进到「给出方案」，为财政投入和招商引资提供量化依据。

## 场景三：老人的 15 分钟和年轻人不一样

**角色**：社区养老服务中心负责人李主任
**痛点**：常规评估按成年人步速计算，老年人步速明显更慢。很多设施在报表上显示可达，老人实际走不到。

**使用流程**
1. 在参数面板切换到「适老模式」，步速从默认约 1.2 m/s 调整为约 0.8 m/s。
2. 地图上叠加显示两个等时圈：成年人 15 分钟圈和老年人 15 分钟圈，两者之间的差距一目了然。
3. 系统重新统计老年人步行 15 分钟内可到达的社区卫生服务中心、药店、菜市场和养老驿站。
4. 询问 AI 助手：「这个小区的老人看病方便吗？」AI 结合适老模式的计算结果作答，并指出需要重点关注的楼栋片区。

**价值**：让适老化改造、养老驿站布点有了针对老年人的数据支撑。

## 场景四：多个社区横向对比

**角色**：区住建局规划人员
**痛点**：需要从辖区多个社区中找出生活圈建设最薄弱的一批，优先安排改造资金。

**使用流程**
1. 依次添加多个社区中心点，或上传坐标列表进行批量体检。
2. 系统并发完成计算，已经算过的区域直接读缓存，重复查询不再调用接口。
3. 在对比视图中查看各社区的总分排名、分项雷达图叠加和盲区面积柱状图。
4. 导出对比表格，作为改造优先级排序的依据。

**价值**：统一口径、统一算法，横向可比，避免各社区自报数据口径不一致。

## 场景五：买房 / 租房前的生活便利度评估

**角色**：准备在某新区买房的年轻家庭
**痛点**：售楼处宣传「步行可达学校、商超」，实际要绕路、过天桥，走起来远远不止几分钟。

**使用流程**
1. 在地图上点击意向小区，或输入小区名称。
2. 查看 15 分钟等时圈内是否有小学、幼儿园、菜市场、社区医院，以及到每处设施的**真实步行时间**。
3. 用自然语言提问：「孩子上最近的小学要走多久？路上要过几次马路？」
4. 同时对比两个候选小区的评分雷达图，辅助决策。

**价值**：用真实路网数据核实宣传，把「便利」变成可以量化比较的数字。

## 场景六：商户开店选址

**角色**：连锁药店拓展经理
**痛点**：想找到有居住人口、但周边药店覆盖不足的位置。

**使用流程**
1. 在目标区域内选择多个中心点进行体检，筛选出「药店盲区」。
2. 结合选址推荐结果，得到候选开店点位。
3. 导出点位清单与覆盖分析，供拓展团队实地考察。

**价值**：在公共服务缺口处开店，既能满足居民需求，也更容易获得客流。

## 附：异常情况下的使用体验

| 情况 | 系统表现 |
|---|---|
| 未配置 API Key | 自动进入**离线演示模式**，回放预置的样例社区数据，功能完整可体验 |
| 接口触发 QPS 限流 | 请求自动排队、退避重试，界面显示进度，不报错中断 |
| 某次接口调用失败或超时 | 使用「直线距离 × 绕路系数」进行估算，系数由已采样的真实数据标定，结果标注为「估算」 |
| 某类 POI 检索为空 | 自动换用同义关键词和分类重新检索；确认确实没有时，标记为盲区而不是报错 |
| 同一区域重复查询 | 直接读取缓存，秒级返回，不消耗接口配额 |
